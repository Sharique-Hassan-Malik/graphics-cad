# Architecture

```
TileSet (tiles + socket adjacency)         (tiles.py)
        │  precompute compat[direction][a, b]
        ▼
   collapse: observe → propagate → (restart on contradiction)   (solver.py)
        │  grid of tile indices
        ├──▶ verify: re-check every edge          (verify.py)
        ├──▶ render: stamp tiles → PNG            (render.py, image.py)
        └──▶ terrain only: corner lattice → island mesh → Blender   (model3d.py, blender_export.py)
```

## 1. Tiles and sockets (`tiles.py`)

A **tile** carries four edge *sockets* — labels for its north, east, south, and west borders — plus a small bitmap and a frequency weight. Adjacency is defined entirely by sockets: two tiles may be neighbours exactly when the sockets on their touching edges are equal. Tile A can sit to the west of tile B iff `A.east == B.west`.

The labels are chosen so that "sockets match" means "the border pixels line up." In the **pipes** set a socket is `open` or `shut`, and a pipe only connects to a pipe. In the **terrain** set a socket is the *pair of corner materials* along that edge (`(land, water)` etc.), so a shared edge must agree on both of its corners — the Wang-tile scheme, which is what makes coastlines continue unbroken from one tile to the next.

The whole tileset is compiled once into an adjacency oracle: `compat[d]` is an `n × n` boolean matrix where `compat[d][a, b]` is true iff `b` may sit in direction `d` from `a`. Building it is the only place sockets are compared; the solver afterwards only ever indexes this matrix, which is what keeps propagation fast. A useful invariant, checked in the tests, is `compat[E] == compat[W]ᵀ` — "b may sit east of a" is the same statement as "a may sit west of b."

Rotated variants (a pipe elbow in four orientations) are generated by rotating both the socket 4-tuple and the bitmap together, so a rotation stays internally consistent.

## 2. The solver (`solver.py`)

Each cell holds a boolean row over the `n` tiles — its *superposition*, initially all true. The main loop is two steps.

**Observe.** Among cells with more than one option left, pick the one of lowest **entropy** and collapse it. Entropy here is the weighted Shannon entropy of the cell's remaining options — a cell with two equally-likely tiles is more settled than one with five, and using the frequency weights (not just the count) makes the choice track the tile distribution. A minuscule random jitter breaks ties, and it is the *only* randomness besides the weighted pick of which tile to collapse to, which is what makes a run a pure function of the seed. Collapsing means setting the row to a single chosen tile.

**Propagate.** A collapse removes options from the collapsed cell, which can make some options in its neighbours impossible — any neighbour tile not compatible with *some* surviving option across the shared edge. Those removals can cascade. The propagation is a worklist: pop a changed cell, and for each direction compute the set of neighbour tiles still supported (`compat[d][row].any(axis=0)` — "allowed if compatible with any option here"), intersect it into the neighbour, and if the neighbour shrank, push it. The loop ends at a fixpoint where no cell can eliminate anything from another — exactly arc-consistency (AC-3) specialised to a grid.

**Contradiction and restart.** If propagation empties a cell (no legal tile), the partial assignment cannot be completed. The overlapping-model WFC would backtrack; this simpler tiled model restarts from scratch, drawing from the same seeded generator so the sequence of attempts is itself deterministic. For well-behaved tilesets (both here) the first attempt almost always succeeds, so the average attempt count is essentially 1.

**Border constraints** are applied before the main loop by intersecting the outer cells' rows with "tiles whose outward socket equals the required label," then running one propagation pass — a clean way to say "fence this pipe network" or "surround this island with water."

## 3. Verification (`verify.py`)

The solver is *supposed* to guarantee legality, so the verifier assumes nothing about it. Given only the final grid of tile indices, it walks every interior edge and asks the tileset whether that neighbour pair is allowed, returning each violation as `(row, col, direction, a, b)`. On a correct run the list is empty for every seed — the headline result. Verifying independently is the point: a bug in propagation that produced an illegal tiling would be caught here rather than hidden behind it.

## 4. Rendering, and a from-scratch PNG (`render.py`, `image.py`)

Rendering is just stamping: place each tile's bitmap at its grid position. Because adjacent sockets match and sockets encode borders, the result is seamless with no blending. The image is written by a small hand-rolled PNG encoder — signature, `IHDR`, a `zlib`-compressed `IDAT` of filtered scanlines, `IEND`, each chunk CRC-tagged — so the only third-party dependency in the whole project is NumPy.

## 5. Lifting terrain into 3D (`model3d.py`, `blender_export.py`)

This is where the terrain tileset's design pays off twice. Each terrain tile is keyed on its four corner materials, and WFC guarantees neighbouring tiles agree on the corners they share. Therefore the grid of tile *corners* — an `(H+1) × (W+1)` lattice — is globally consistent: every interior corner has a single well-defined land/water value, assembled from whichever tiles touch it. `terrain_lattice()` builds it and *raises an error if any shared corner disagrees*, which can only happen if adjacency was violated — so a successful lift is a second, structural proof of legality, independent of the edge-by-edge verifier.

That binary lattice is a heightmap. `island_mesh()` turns it into a watertight slab: a stepped top surface (land raised, water low), a flat underside, and side walls around the perimeter — every edge shared by exactly two triangles, checked in the tests. `blender_export` rebuilds it with `from_pydata`, assigns land and water materials by face height, and renders it headless with Cycles. As with the rest of the repo, Blender is optional: the 2D tiling is fully generated and verified without it.
